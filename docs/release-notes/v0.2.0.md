Patchbay 0.2.0 — measure the loudness, don't guess it

Presets in a setlist drift apart in level, and the usual fix is to walk back to
the amp between songs and turn something. This release measures instead: record
one riff, play it into every preset in turn, and read what each one is off by in
LUFS. The Leveling screen was then rebuilt around that — a full-height input
meter, a looper-style transport, one row per preset — and a handful of things
that were quietly wrong on the wire got fixed on the way.

`qc_mcp` moves too, for the first time since 0.1.2: fourteen new tools, four new
modules, and one long-standing protocol mistake corrected.

## Measured preset leveling

- **Record a reference riff** — arm it, play, stop playing. The take is the dry
  DI off `USB 1/2`, so it is your instrument with no preset on it, and the same
  signal reaches every preset that gets measured. `space` works the whole
  recorder: arm, stop, discard.
- **No guitar to hand?** Five riffs ship with the bench — chords, chug,
  dynamics, lead, sweep — synthesised on first use, always identical, and loud
  enough to measure with. Pick one from *Source*.
- **Measure all** recalls each preset, plays the riff through it over the USB
  reamp path, and reports integrated LUFS, true peak and the correction it
  needs. Nothing is written. The proposal is **editable** before anything moves:
  the measurement is a good opinion about loudness and a bad one about taste, so
  a lead that should sit two dB above the rest can say so.
- **Apply** moves the lane output fader on the device — audible, undoable, and
  *not* in the preset file until you save. **Save** writes it in.
- **Scenes** get the same treatment inside one preset, on a Gain block's LEVEL
  rather than the lane (a lane holds one level for the whole preset, a Gain
  block holds eight).
- **Is the take any good?** A riff that is quiet or mostly gaps produces numbers
  that look exactly like preset differences. The transport says so — the first
  riff ever recorded against this feature peaked at −22.8 dBFS with three
  quarters of its samples near silence, and nothing anywhere said a word.

Measuring is silent in the room: the output is tapped to USB while it runs. See
[docs/LEVELING.md](https://github.com/lexasoft123/qc-mcp/blob/main/docs/LEVELING.md)
and [docs/METERS.md](https://github.com/lexasoft123/qc-mcp/blob/main/docs/METERS.md).

**The measured half needs an optional dependency that a packaged Patchbay does
not install.** The app sets up `qc-mcp` with no extras, so the transport reports
*"Measured leveling needs the audio extra"* until you run
`pip install -e '.[audio]'` in the repo it created. Everything by ear — the
faders, the meters, the scenes, the output dock — works without it. Making the
app offer that install is the obvious next job.

## The Leveling screen, rebuilt

It drew the same five presets three times — as report rows, as cards in a strip,
and their scenes twice over — about 1400 px of content in a 788 pt window.

- **A full-height input meter** down the left edge. A level is easier to judge
  over 600 pt than over 40, and this is the value that matters at every step.
  Peak hold (1.6 s, then 24 dB/s), a clip LED, and the arm threshold drawn on
  the scale so *"why has it not started"* is visible. It follows the DI while
  the recorder is armed or rolling and the outputs the rest of the time.
- **A looper transport**: REC and PLAY, a tape strip, three readouts, one line
  of verdict. The state lives in the buttons' faces rather than in a paragraph
  beside them.
- **One 44 pt row per preset** — include, name, live meter, where the fader is
  now, LUFS, true peak, off by, the change to be written, and what it will be
  after. The focused row opens a **drawer** for the things that need the preset
  actually loaded: its output lanes, its scenes, the by-ear knob.
- **Nothing jumps.** Every band whose content varies keeps its size; only the
  rows scroll. That is now an acceptance criterion with a check behind it, not a
  nicety — `harness/nojump.html` walks the view through arm → record → play →
  measure → apply → drawer → focus with a `ResizeObserver` on every band and
  reports any band that moved.
- **Exactly one accented button at a time**, walking the job: REC → Measure all
  → Apply → Save.
- **The input trim is on the screen now.** A take that is "too quiet to measure
  with" is usually a low input gain, and that control lived three screens away
  in I/O Settings. It sits under the meter, labelled `global · I/O`, because
  unlike everything else there it is a device-wide setting — which is also why
  the first write in a session asks first.

## Fixed

- **Disconnect segfaulted the daemon.** Since `close()` began sending its own
  `Connection` frame, every `SIGTERM` killed the process with `EXC_BAD_ACCESS`
  instead of stopping it: the handler closes, `sys.exit()` unwinds
  `serve_forever()`'s `finally: close()`, and the second pass handed a NULL
  device to `IOHIDDeviceSetReport`. No traceback, no exception — the button just
  crashed Python. Guarded on both backends, and `close()` is idempotent.
- **Disconnect did not stick**: the autoconnect tick had no memory of it and
  brought the daemon straight back.
- **A crashing Cortex Control relaunched forever.** Bridge starts are budgeted
  now — three deaths inside a minute and Patchbay gives up, says so once, and
  waits for you. (The crash itself is in the app's own protobuf parser and is
  contained here, not cured.)
- **Auto mode is gone.** It was a third thing to understand that only ever
  guessed at the two real answers; the preference migrates to Bridge.
- **A save made every later recall return the previous preset.** The bench
  confirms a recall by listening for the `RecallPreset` payload the device
  broadcasts — and a File CREATE makes the device broadcast one too, which
  nothing consumed. After a Save-all, `open(B)` returned A's grid and `open(A)`
  returned B's, for the rest of the session.
- **Save-all wrote nothing.** It reopened each preset and saved it, but the
  recall reloads the file *over* the trim in the working grid, so it saved the
  file onto itself. It now re-applies each known trim after its recall.
- **`P` twice started two playbacks** and the Stop button was
  `disabled={playing}`, so it could not be pressed. One playback flag, cleared
  only when the service says the sound ended.

## On the wire

- **Per-scene bypass was writing to the wrong parameter.** A block's bypass
  control is **one past its last readable param** — `len(model.params)` from a
  device read — and this was hardcoded to `4`, which is a real knob on anything
  but a four-slot block: VOLUME on a Neural Capture, TONE CUT on a UK C30
  TopBoost, LOW PASS on a Tape Delay. That, and nothing about trails, is the
  whole of the old "silent no-op on Delay blocks" note. Captured off Cortex
  Control's own right-click *Assign to Scenes*; verified on amp, reverb,
  capture, cabsim, delay and IR blocks.
- **Input level is a preamp trim, not a fader: IN 1 is −12 … +60 dB.** ModelRepo
  declares the IOSettings levels as a literal `min=0 max=1`, so the generic
  range code believed the display range *was* 0–1 and converted nothing.
  Measured against the app's own I/O panel.
- **`input_type` is 0 = Instrument, 1.0 = Mic.** It was documented as a
  three-position control with 1.0 = Line, which reported a condenser on input 2
  as a *line* input. 0.5 has never been observed on a device.
- New tools: `output_meter`, `audio_devices`, `sample_arm` / `sample_status` /
  `sample_stop` / `sample_discard`, `measure_loudness`, `measure_preset`,
  `compare_presets`, `suggest_levels`, `level_preset`, `level_scenes`,
  `level_setlist`, `assign_expression`.
- **One record says who holds the device.** `session.json` beside the socket —
  pid, owner, mode, firmware, who launched it — replaces inferring ownership
  from `pgrep`, a FIFO or a socket probe, any of which could be true about a
  different world. A socket file outlives the process that made it, and a
  process can outlive its socket; that is what the lock exists to end.

## From contributors

- **[@jnskender](https://github.com/jnskender)** fixed setlist bank labels on the
  Quad Cortex Mini ([#18](https://github.com/lexasoft123/qc-mcp/pull/18)) — four
  footswitches means banks of four, so a Mini preset at position 9 is 3B on the
  device and the tool was calling it 2B — and added **expression-pedal
  assignment** ([#19](https://github.com/lexasoft123/qc-mcp/pull/19)), which is
  the Quad Cortex's only route to per-parameter MIDI control. The encoding was
  reverse-engineered from a preset that already carried assignments.
- **[@MaKiGiO](https://github.com/MaKiGiO)** found that a Windows shared handle
  was handshaking beside Cortex Control and making the device drop the app's
  subscriptions — "Device connection lost", seconds after every connect. It
  sniffs the wire for 1.5 s first now and rides an existing session instead
  ([#20](https://github.com/lexasoft123/qc-mcp/pull/20)). Also full hex frame
  logging in the Windows interceptor
  ([#21](https://github.com/lexasoft123/qc-mcp/pull/21)) and, with it, a
  captured-and-replayed account of the device's **file operations** — copy,
  delete, rename, setlist create
  ([#22](https://github.com/lexasoft123/qc-mcp/pull/22)).

Thank you both.

## Windows

Still unsigned: SmartScreen asks on first run, **More info** → **Run anyway**.
The installer the updater downloads is the same.

The Leveling rebuild has **not been looked at on Windows hardware**. Its layout
is checked at the app's real width and there is a test that keeps every blurred
surface off that path — the field machine's integrated GPU makes
`backdrop-filter` expensive — but the screen itself has only been driven on
macOS. The MCP server and the daemon are verified on Windows 10 22H2 with
CorOS 4.1.0.

## Verified

On hardware, CorOS 4.1.0, direct mode: Disconnect stops the daemon cleanly
(exit 0, where the same `SIGTERM` gave 139 before the fix); the IN 1 trim writes
and reads back, 0 → +3 → 0 dB; a recall lands in under a second and the row
shows a skeleton while it does; Apply → Save-all → recall another preset →
recall back finds the trim still there, where the same sequence beforehand read
the *other* preset's lane; the rail follows the DI while armed and the outputs
otherwise; Listen-to-set walks the bench and `esc` stops it.

Offline: the Python suite (18 files) on macOS and Windows, 155 app tests, three
typecheck projects, and the no-jump harness — clean.

## Getting it

macOS: the arm64 dmg for Apple Silicon, x64 for Intel; signed and notarized.
Windows: the `.exe` installer. Patchbay updates itself from here.
